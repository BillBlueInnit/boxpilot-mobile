# BoxPilot for Android and iOS

The phone version of [BoxPilot](https://github.com/BillBlueInnit/boxpilot): the same proxy client
with the same built-in subscription converter. It runs the core as the device VPN, with no
separate download.

One React Native (Expo) codebase, with each platform's own controls:

- **Android** (10 and later): Material 3 with Material You colours, a Quick Settings tile, and a
  VPN notification with a Disconnect action.
- **iOS** (16.4 and later): the system's own tab bar, navigation bar, toolbar buttons and menus,
  search, switches, segmented controls, action sheets and alerts. On iOS 26 these are Liquid Glass.

## What it does

The same as the desktop app, because it runs the desktop app's engine (`boxpilot-core`)
unchanged:

- Subscriptions: v2ray/Shadowrocket links, Clash / Clash.Meta YAML and sing-box JSON. Covers
  VLESS (REALITY, Vision), VMess, Trojan, Shadowsocks, Hysteria 2, TUIC, AnyTLS, WireGuard and more.
  Includes interval and startup updates, include/exclude filters, traffic and expiry info, pasted
  (local) subscriptions, and one-tap import links (`clash://`, `clashmeta://`, `sing-box://`,
  `boxpilot://`).
- Local nodes: add single nodes from share links, and copy any node or a whole subscription as
  share links.
- Proxies: Rule / Global / Direct modes, selector and Auto groups per subscription, latency, real
  latency and speed tests, and countries (measured through the node when possible). Auto picks
  nodes by quickest, steady, list order or most bandwidth, optionally limited to one region.
- Rules: built-in China bypass and ad blocking, rule-sets from URLs or files (sing-box, Clash,
  ACL4SSR), ACL4SSR `.ini` import, a node group of its own for a rule-set, and custom rules. A
  connection can be turned into a rule from the Connections page.
- DNS (DoH/DoT/DoQ/UDP, FakeIP, IPv6), UDP and QUIC options, LAN sharing (hotspot), per-app
  proxy (Android).
- Live traffic chart, connections (close one or all), logs, and the generated config.
- English, 简体中文, 繁體中文 and Русский (the desktop's translations).

## How it fits together

```
React Native UI (src/)              Material 3 on Android, UIKit controls on iOS
   │  one native module: invoke(method, json) + events
Rust bridge (rust/) → boxpilot-core::Engine   state, scheduler, converter, config, Clash API
   │  CoreHost: start(config) / stop()
Platform host (modules/boxpilot-core, native/)
   │                                Android: BoxVpnService (VpnService)
   │                                iOS: PacketTunnel network extension
libbox (sing-box)                   the core, in-process, serving the Clash API on 127.0.0.1
```

The engine reaches the core only through the generated config and the Clash API, as on desktop.
The only mobile-specific piece is `CoreHost`: instead of spawning the sing-box executable, the
engine asks the platform to run libbox inside its VPN service.

The bridge has one entry point, `invoke(method, argsJson) -> json` (`rust/src/api.rs`), and one
event stream. Nothing is generated: following a new core version means a match arm in `api.rs`
and a typed wrapper in `src/core/engine.ts`. On Android the engine lives in the app process, not
in the JavaScript runtime, so the VPN, the tile and the engine's scheduler keep working after the
UI is closed.

`android/` and `ios/` are generated by `npx expo prebuild` from `app.json` and
`plugins/with-boxpilot.js`, and are not committed. The app's own native code is in
`modules/boxpilot-core` (Kotlin and Swift) and `native/ios` (the packet tunnel extension).

## Building

Requirements: Node 24, Rust with the mobile targets and `cargo-ndk`, Go 1.25+, and the Android SDK
with NDK 28.2 (Android) or Xcode 26 (iOS).

```bash
npm ci
```

Android:

```bash
bash scripts/build_libbox.sh android
```

```bash
bash scripts/build_rust.sh android
```

```bash
npx expo prebuild --platform android --no-install
```

```bash
cd android && ./gradlew assembleRelease
```

iOS, on a Mac:

```bash
bash scripts/build_libbox.sh apple && bash scripts/build_rust.sh ios
```

```bash
npx expo prebuild --platform ios && ruby native/ios/add_packet_tunnel.rb
```

Then build `ios/BoxPilot.xcworkspace` with Xcode.

`rust/Cargo.toml` takes `boxpilot-core` from GitHub. To build against a local checkout of the
desktop repository, add `.cargo/config.toml` (ignored by git):

```toml
[patch."https://github.com/BillBlueInnit/boxpilot"]
boxpilot-core = { path = "../../rust/boxpilot/crates/core" }
```

Checks and scripts:

- `npx tsc --noEmit`, `npm run lint`, `npm test`.
- `python scripts/gen_i18n.py` regenerates `src/i18n/strings.desktop.ts` from the desktop
  translations.
- `python scripts/make_icons.py` renders the icons from the desktop icon's geometry.
- `.maestro/` holds the UI tours CI runs on an Android emulator (including a real VPN connection
  through a test node) and on an iOS simulator.

## Releases

`.github/workflows/build.yml` runs the checks, then builds:

- APKs (one per ABI; most phones want arm64-v8a), signed with the release key when the
  `BOXPILOT_KEYSTORE_*` secrets are set;
- an unsigned IPA. Re-sign it with a provisioning profile that has the Network Extension
  (packet tunnel) and App Group capabilities. That requires a paid Apple developer account,
  because free accounts can't use Network Extension.

Push a `v*` tag to publish both to GitHub Releases.
